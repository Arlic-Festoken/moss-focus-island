# Moss 计划与手记设计

## 产品目标

“计划”不是另一个待办清单，而是专注前后的同一页：

1. 在未来某天写下一件要做的事。
2. 关联已有 Moss 任务，或在开始时把计划转成任务。
3. 从计划页直接启动五分钟点火或标准专注。
4. Moss 把完成情况和专注时长自动写回当天记录。
5. 用户可导入 Apple 手记导出的 PDF / 文本，和 Moss 的专注记录一起回看。

## 信息架构

主侧边栏新增“计划”，位于“今天”和“时间线”之间。

计划页采用安静的双栏布局：

- 左栏是时间导航：今天、未来、手记，以及对应条目列表。
- 右栏是一张“纸页”：显示日期、标题、正文、预计用时、关联任务和执行操作。
- 空状态显示“今日一页”，包含待做数量、预计用时和最近专注记录。

## 视觉与交互

- 借鉴 Apple 手记的日期叙事、留白、柔和渐变和单页编辑感，不复制其私有内容或品牌资产。
- 大容器保持稳定，不做浮动；仅按钮、日期胶囊和小条目使用轻量果冻反馈。
- 选择变化使用短距离位移和透明度过渡，避免大面积弹跳。
- 完成状态用低饱和绿色，逾期用暖杏色，不使用突兀的纯红色。

## 数据边界

- `PlanEntry` 保存计划本身，可选关联一个 `FocusTask`。
- `JournalRecord` 保存手记式记录，来源可以是 Moss 或 Apple 手记文件导入。
- 所有数据进入现有 `moss-data.json`，沿用原子写入与备份机制。
- Apple 手记没有供 macOS 第三方应用直接读取既有条目的公开接口；只支持用户主动导出。因此 Moss 只提供显式文件导入，不尝试访问受保护的手记数据库。

## LLM 边界

第一版不依赖 LLM，确保离线、即时和私密。

后续可以加入可选的本地或用户自选模型，且只生成草稿：

- 把长计划拆成可专注的小步骤。
- 根据个人历史给出预计时长。
- 把一周的计划、专注和手记整理成复盘草稿。

模型不得静默修改计划、自动启动计时或默认上传手记正文。
