# Moss Today 紧凑任务库设计

日期：2026-07-26  
状态：视觉方向已确认，待书面规格复核

## 背景

Today 页当前把每个可开始任务渲染为一条占满项目容器的横向行。任务标题通常只有几个字，但详情和操作被推到最右侧，导致中间出现大片无意义空白。单个项目包含十余个任务时，这种结构也会让 Today 页纵向无限增长，使“现在做什么”被完整任务库淹没。

本次改动只重构 Today 页的任务展示与任务换组体验，不改变专注计时、历史记录、成长志、归档和项目编辑模型。

## 体验目标

1. 常规 Moss 窗口中，任务以两列短卡片排列；更宽窗口使用三列，窄窗口退回单列。
2. 一个任务的标题、累计数据和开始按钮彼此相邻，不再横跨整行。
3. 同一时间只展开一个项目。默认展开最近使用任务所属项目；没有历史时展开第一个非空项目。
4. 展开项目先显示 6 个任务，剩余任务通过“展开另外 N 项”按需出现。
5. 用户可以抓住任务手柄，把任务直接拖入另一个项目。
6. 拖拽不是唯一入口：任务菜单同时提供“移动到项目”，供键盘和辅助功能用户使用。
7. 移动任务只影响未来任务归属，不改写任何既有专注记录。

## 信息架构

### 项目层

Today 页继续展示全部非归档、非空项目，但采用手风琴结构：

- 展开的项目显示项目图标、名称、任务数、累计专注、添加、更多和收起操作。
- 收起的项目只显示一行项目摘要。
- 打开另一个项目时，前一个项目自动收起，避免多个长列表同时出现。
- “未分类”使用稳定的分组标识，不再在每次视图刷新时生成临时项目 ID。

### 任务层

展开项目内部使用自适应网格：

- 网格使用最小宽度 210 pt、最大宽度 270 pt、间距 8 pt 的自适应列。
- 当前常规 Moss 窗口形成 2 列；容器能容纳 3 个最小宽度单元时形成 3 列。
- 容器不足以容纳 2 个最小宽度单元时退回 1 列。
- 默认显示前 6 个任务。
- 单个任务卡包含拖拽手柄、标题、累计专注、完成段数、更多菜单和开始按钮。
- 项目图标不在每张任务卡重复出现；项目头已经承担类别识别，移除重复图标可以显著降低宽度。
- 任务标题允许单行截断，完整标题通过辅助功能标签和悬停提示读取。

## 展开与排序规则

首次进入 Today 页时：

1. 如果当前正在专注或等待复盘，展开当前任务所属项目。
2. 否则展开 `preferredStartTask` 所属项目。
3. 若首选任务不存在，展开第一个非空项目。
4. 未分类任务使用稳定的 `.ungrouped` 分组标识。

项目顺序继续服从现有 `FocusProject.sortOrder`。项目内任务继续服从现有 `FocusTask.sortOrder`。展开全部只是显示状态，不改变排序或持久化数据。

## 拖放交互

### 拖动

- 只有拖拽手柄启动移动，降低点击“查看详情”时误拖的概率。
- 当前正在专注或等待复盘的任务不能拖动，行为与现有编辑、归档限制一致。
- 拖动时任务卡出现轻微缩放和透明度变化；遵循“减少动态效果”设置。

### 放置

- 每个其他项目的项目头都是放置目标。
- 指针进入目标时，项目头显示鼠绿色描边和“移到这里”提示。
- 放置成功后：
  - 任务的 `projectID` 更新为目标项目；
  - 任务的 `category` 同步为目标项目名称；
  - 任务追加到目标项目的末尾；
  - 原项目和目标项目的任务数立即更新；
  - 显示简短提示“已将「任务」移到「项目」”。
- 放到当前项目时不做写入。
- 非法、归档或不存在的目标不会修改数据。
- 历史 `FocusSession.projectID`、`projectTitle` 和 `category` 保持不变。

### 无障碍替代

任务更多菜单新增“移动到项目”子菜单，列出其他可用项目和“未分类”。该入口：

- 可用键盘操作；
- 具有明确的 VoiceOver 标签；
- 与拖放调用同一个 `DataStore.moveTask` 数据路径；
- 当前任务专注期间禁用，并说明原因。

## 代码边界

### `TodayTaskPresentation`

新增纯展示模型，负责：

- 把项目和可开始任务组装为具有稳定 ID 的 `TodayTaskGroup`；
- 生成项目顺序和未分类分组；
- 选择默认展开项目；
- 根据 6 项限制返回可见任务和剩余数量。

该模型不读写磁盘，也不持有 SwiftUI 状态，可直接行为测试。

### `DataStore.moveTask`

新增唯一的任务换组写入方法：

- 验证任务和目标项目；
- 更新 `projectID`、`category` 和目标项目内末尾 `sortOrder`；
- 排序并保存；
- 返回是否发生了移动。

它不会更新历史记录。当前专注限制由调用层根据 `AppStore` 状态执行。

### Today 视图组件

- `TodayView` 持有单一 `expandedGroupID`。
- `ProjectTaskSection` 接收展开状态、折叠回调和放置回调。
- `CompactTaskTile` 替代满宽 `TaskCapsuleRow`，保留现有开始、5 分钟、详情、编辑、归档和删除能力。
- 网格与拖放只影响 Today 页；菜单栏和其他任务入口保持不变。

## 状态与错误处理

- 当展开项目因归档或任务全部移走而消失时，自动选择新的默认非空项目。
- 拖放载荷无法解析时忽略，不产生部分写入。
- 保存失败继续使用现有 `DataStoreIssue` 机制提示，不新增第二套错误系统。
- 如果目标项目在拖动期间被归档，`moveTask` 返回失败，界面保持原状态。

## 测试策略

### 行为测试

先写失败测试，再实现：

1. 展示模型生成稳定的项目分组和未分类分组。
2. 默认展开最近使用任务所属项目。
3. 默认只返回前 6 个任务并给出正确剩余数量。
4. 移动任务会更新 `projectID`、`category` 和目标项目内顺序。
5. 移动后重新加载数据库仍保留新归属。
6. 移动任务不会改写既有专注记录。
7. 移到当前项目、归档项目或不存在项目时不写入。

### UI 合约

`ui-regression-check.sh` 检查：

- Today 使用自适应 `LazyVGrid`；
- 存在 6 项渐进展示上限；
- 存在拖放目标和移动菜单；
- 不再由 `ProjectTaskSection` 直接为所有任务输出满宽 `TaskCapsuleRow`。

### 实机验收

使用用户当前真实数据验证：

- “学业主线”13 个任务在常规窗口中只占 3 行；
- 项目下方显示“展开另外 7 项”；
- 打开另一项目会收起当前项目；
- 任务标题和开始按钮之间不存在大片空白；
- 拖到另一项目后两个项目计数正确更新；
- 由于实机拖动会修改用户数据，验收后将测试任务移回原项目；
- VoiceOver 能读取任务、累计数据、开始和移动操作；
- 浅色、深色、减少动态效果下布局稳定。

## 验收标准

1. 用户截图中的满宽任务行不再出现。
2. 常规窗口默认最多显示一个项目的 6 张短任务卡。
3. 任务卡在常规窗口形成两列，在更宽空间形成三列。
4. 全部原有任务操作仍可达。
5. 拖放和菜单移动都能可靠换组，并持久化。
6. 旧专注历史保持不变。
7. 全量 UI、类型、行为测试和发布构建通过。
